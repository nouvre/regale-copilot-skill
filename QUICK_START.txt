QUICK START — Build a Regale demo with GitHub Copilot
=====================================================

You describe the demo in chat. Copilot drives Regale's built-in browser,
clicks through the product, and turns each screen into a slide with your
talk track attached.

You do not click through the product yourself. You do not need a URL for
every screen.


BEFORE YOU START
----------------

1. Regale Studio is installed and running.
2. A Regale project is open (File -> New, or open an existing one).
3. The Copilot assets are installed. From this folder, double-click:
      install-regale-demo.cmd
   It checks everything it needs, installs, then offers to restart Copilot
   for you. Say yes -- Copilot only reads the new files at startup.

Full setup instructions: WINDOWS_COPILOT_APP.md


BUILD A DEMO
------------

1. Open the GitHub Copilot app.

2. Type /agent and pick "Regale Demo".

3. Describe the demo in plain language, for example:

      Pitch SharePoint to an executive. Keep it short and lead with
      business value.

4. You get a storyboard preview — scenes, timings, narration. Nothing has
   touched Regale yet.

5. Adjust it with short commands:

      rename scene 2 "Search the intranet"
      edit duration scene 1 30
      edit narration scene 3: "Close on faster decisions."
      add beat scene 2: open the search results
      remove beat scene 2: 1
      reorder scene 3 1

6. When it looks right, type exactly:

      confirm build

   That phrase, and only that phrase, starts the build.


WHAT HAPPENS DURING THE BUILD
-----------------------------

- Copilot checks Regale's permissions and asks up front if anything it
  needs is switched off.
- It sets up the project title and turns on Presenter View.
- It opens Regale's browser and navigates to the product.
- It captures each screen, drops a click hotspot, and writes your
  narration into the presenter notes.
- It finishes with a saved project for you to review.

It does NOT publish. Publishing stays your decision — do it from Regale
when you are happy with the demo.


SIGNING IN
----------

The first time you build against a product, Copilot pauses and asks you to
sign in inside Regale's browser window. Sign in there once, including any
MFA prompt, and tell it you are done. It picks up exactly where it stopped
— nothing you have already built is lost.

That sign-in is remembered, so later builds should not stop.

Copilot never types your password and never reads a saved one.

Some sites sign you out between sessions regardless. If it asks again, just
sign in again — that is the site's behaviour, not a fault.


IF SOMETHING LOOKS WRONG
------------------------

- It answers with a normal pitch instead of a storyboard
     -> "Regale Demo" was not selected. Pick it under /agent and retry.

- It starts building without mentioning permissions or sign-in
     -> It did not read the build instructions. Ask it:
        "did you read BUILD_PIPELINE.md?"
        If that file is missing, re-run install-regale-demo.cmd

- It says a tool it needs "isn't available" and stops
     -> Run install-regale-demo-all-tools.cmd, restart Copilot, and tell us
        which tool was missing. Builds are slower this way, so switch back
        with install-regale-demo.cmd once it is added to the default list.

- It says the Regale tools are unavailable
     -> Make sure Regale Studio is running with a project open, then
        restart Copilot fully (tray -> Exit).

- It asks for a URL you do not have
     -> Give it your real tenant URL, or pick the public product page.
        It will not guess one, because made-up addresses capture an error
        page instead of the product.

More troubleshooting: WINDOWS_COPILOT_APP.md


THE RESULT
----------

A working draft, not a finished demo. Expect to trim a few slides, nudge a
hotspot, and tighten the narration in Regale before you present it.
